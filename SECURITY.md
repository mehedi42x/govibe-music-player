# Security Policy

## Supported versions

Security fixes target the latest maintained source on the default branch. No stable release has been published yet.

## Reporting a vulnerability

Please do not publish exploit details, credentials, or private user data in a public issue. After the public repository is created, maintainers must enable GitHub private vulnerability reporting / Security Advisories and direct reports to the repository's private **Report a vulnerability** path. Confirm that route works before inviting external contributors. If it is not available, configure a safe private contact method before public launch.

## Response

A maintainer should acknowledge a report, reproduce and assess it privately, coordinate a fix and disclosure window with the reporter, and publish an advisory only when affected users can act on it. Do not include user audio, tokens, or browser-profile data in reports.

The plugin validator is not a sandbox, and community plugin execution is disabled. Security fixes must not imply otherwise.
